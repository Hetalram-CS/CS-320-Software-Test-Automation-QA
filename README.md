CS 320 Software Test, Automation, and Quality Assurance portfolio
## CS 320 Portfolio Reflection

### How can I ensure that my code, program, or software is functional and secure?

I can ensure that my software is functional by carefully following the requirements and testing both valid and invalid inputs. In this course, I used JUnit tests to check the Contact, Task, and Appointment services. I tested normal values, null values, field-length limits, duplicate IDs, and other invalid conditions. I also used code coverage to see how much of my code was tested. To make software more secure, I would validate inputs, handle errors correctly, and continue testing the software whenever changes are made.

### How do I interpret user needs and incorporate them into a program?

I interpret user needs by carefully reading the requirements and turning them into specific program rules. For example, the Contact Service had requirements for the maximum length of IDs and names, the phone number format, and which fields could be updated. I used these requirements when developing the classes and creating my JUnit tests. This helped me verify that the program behaved according to the customer's requirements instead of making assumptions about what the program should do.

### How do I approach designing software?

I approach software design by first understanding the requirements and then breaking the program into smaller parts with clear responsibilities. In Project One, I worked with separate object and service classes for contacts, tasks, and appointments. I also considered testing while developing the program instead of waiting until the end. Testing valid, invalid, and boundary conditions helped me find problems and improve the reliability of my code. In future projects, I will continue using an organized, requirement-based approach so my software is easier to test, maintain, and improve.
